# DAKA AI 经营控制塔

DAKA AI 经营控制塔是一个面向 IP 经营老板的可交互 Demo。它把分散在合同、签名卡表、付款计划、人物名单和外部信号中的信息，转化为老板能看懂、能追问、能采取行动的经营界面。

> 当前版本：`v1.1.0`<br>
> 在线 Demo：[daka-ai-control-tower.seefreefuture.chatgpt.site](https://daka-ai-control-tower.seefreefuture.chatgpt.site/)

## 第一性原理

老板真正需要的不是更多报表，而是更短的决策路径：

```text
事实发生 → 判断经营影响 → 比较方案 → 明确动作 → 跟踪结果
```

因此产品遵循五个原则：

1. **先回答“现在该做什么”**：首页不是数据仓库，而是按影响排序的未来 90 天行动中心。
2. **可视化负责建立全局感，Agent 负责深入讨论**：图表呈现风险、现金和进度；老板可以继续追问依据、假设和备选方案。
3. **从业务对象出发，而不是从部门表格出发**：围绕 IP、人物、合同、账目、签名资源和发行项目建立关联。
4. **事实、信号和建议必须分层**：新闻或传闻不会直接覆盖人物主档；只有确认后的事实才能进入经营数据。
5. **每个判断最终落到行动**：高风险判断应给出优先级、建议负责人、时间节点和影响项目。

## v1.1：决策与责任闭环

v1.1 不再把老板、运营和所有数据揉进一个 Dashboard，而是围绕统一“经营事项”提供两个角色工作面：

- **老板经营总控台**：只看需要拍板的例外、方案比较、事实依据和关键假设。
- **运营 AI 工作台**：查看 AI 已完成的核对、待确认工作、缺失信息与需要升级老板的事项。

两个工作面共享同一个事项状态。老板批准方案后，事项会返回运营执行；运营可以看到老板决定并继续推进。系统同时明确决策权限边界，例如发行延期、核心人物变更、新增成本和合同付款变化。

## 基础能力

- 未来 90 天关键经营行动与发行风险总览
- 20 个 IP 的可扩展组合视图（Demo 内置 3 个示例 IP）
- 付款节点、现金压力和签名资源完成率看板
- IP 人物变动雷达及经营影响映射
- CSV、XLSX、XLS、JSON 数据导入
- D1 结构化记录、R2 原始文件留存与导入审计回执
- 可折叠侧栏和可配置设置抽屉
- 基于当前页面与经营上下文的 GLM 经营 Agent
- 加载、超时、上游业务错误和明确失败提示

## 老板演示路径

建议用 5–8 分钟完成一次演示：

1. 从“未来 90 天 5 项关键行动”开始，建立全局经营感。
2. 打开 AC 米兰或纽卡斯尔联，展示人物、签名资源与发行项目的关联。
3. 进入账目看板，解释未来付款压力。
4. 打开人物变动雷达，强调“外部信号不会直接污染主数据”。
5. 向 Agent 追问：“如果签名延迟两周，有哪些备选发行方案？”
6. 导入一个新 IP 或一组账目，展示系统可扩展而非静态大屏。

## 技术架构

```text
Browser
  ├─ React / vinext UI
  ├─ POST /api/chat
  ├─ POST /api/import
  └─ GET  /api/data
          │
Cloudflare Worker
  ├─ GLM 服务端代理（Secret 读取 API Key）
  ├─ D1：结构化导入记录与审计日志
  └─ R2：原始导入文件
```

主要技术：React 19、TypeScript、vinext、Cloudflare Workers、D1、R2、智谱 GLM。

## 本地运行

要求 Node.js `>=22.13.0`，推荐使用 pnpm。

```bash
pnpm install
pnpm run dev
```

验证生产构建：

```bash
pnpm run build
pnpm exec tsc --noEmit
pnpm run lint
```

## GLM 配置

浏览器只调用本站 `/api/chat`，API Key 不会进入前端 bundle。

服务端需要以下 Secret：

```text
GLM_API_KEY
```

默认模型为 `glm-5.2`。可以通过服务端环境变量覆盖：

```text
GLM_MODEL=glm-5.2
```

当前 v1.1 使用 GLM Coding Plan 的 OpenAI 兼容端点。智谱官方将 Coding Plan 权益限定在其支持的 Coding/通用 Agent 工具范围；若用于正式商业网页，请改用开放平台通用 API Key 与对应端点，并配置正式资源包。

不要把 Key 写入 `.env` 后提交到 GitHub，也不要放进任何 `NEXT_PUBLIC_*` 环境变量。

## 数据导入

公开 Demo 支持 CSV、XLSX、XLS 和 JSON：

- 单次最多 500 行
- 文件最大 5 MB
- IP 主档建议字段：`name, code, kind, contract, owner`
- 账目建议字段：`ip, amount, date, category, status`

公开 Demo 的导入能力用于产品演示，不应上传真实合同、个人信息或敏感财务数据。

## 当前边界

当前版本是“决策入口”，不是完整 ERP：

- 外部新闻为演示信号，尚未接入正式新闻供应商
- 设置项部分用于展示产品方向，并非全部驱动后端策略
- 暂未实现组织权限、审批流和生产级租户隔离
- 暂未接入正式合同系统、供应链系统和销售系统

下一阶段应优先建设：可溯源经营事实层、方案对比工作台、Agent 生成行动并进入审批、供应链节点与发行项目联动。

## 安全

- API Key 仅存储为服务端 Secret
- 上游错误按业务码处理，不伪造 Agent 回复
- 导入文件与结构化记录分开保存并生成审计回执
- 新闻信号与确认事实分离
- `.env*`、构建目录和本地 Worker 状态均已加入 `.gitignore`
