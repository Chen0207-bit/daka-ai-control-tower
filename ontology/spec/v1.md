# DAKA Ontology DSL v1 规范

状态：v1.0.0（authoring 契约）。Runtime 只消费由编译器产出的 Canonical IR；本文件约束 YAML authoring format。

## 1. 文件与模块

- Schema 以目录为单位组织，目录内所有 `*.yaml` 文件按文件名字典序加载，合并为一个 ontology document。
- 每个文件是一个 YAML mapping；顶层 key 必须是第 3 节定义的 section 之一。
- `imports` 保留给跨目录引用；v1.0 的加载单位为单目录，跨目录 import 在编译器后续版本实现。
- Schema YAML、Data Pack YAML、Connector Mapping YAML 是三种不同文档，不得混写。本规范只约束 Schema YAML。

## 2. 标识与命名

| 对象 | 规则 | 示例 |
|---|---|---|
| ontology 名 (`meta.name`) | kebab-case | `daka-business-ontology` |
| interface / objectType / linkType ID | PascalCase `^[A-Z][A-Za-z0-9]*$` | `Contract`, `RightsGrant` |
| valueSet / action / rule / policy / projection / connector ID | camelCase `^[a-z][A-Za-z0-9]*$` | `paymentStatus`, `paymentSettlesSchedule` |
| property 名 | camelCase | `dueAt`, `contractNumber` |

同一 section 内 ID 在目录范围全局唯一；重复 ID 是语法错误（`DSL1005`）。

## 3. Sections

| Section | 内容 | 键 ID 规则 |
|---|---|---|
| `meta` | ontology 元信息（见第 4 节） | — |
| `imports` | 保留：跨目录引用列表 | — |
| `valueSets` | 枚举值集合 | camelCase |
| `interfaces` | 可复用属性接口 | PascalCase |
| `objectTypes` | 对象类型，可 `implements` interface | PascalCase |
| `linkTypes` | 关系类型：`from`/`to`/`cardinality` | camelCase |
| `actions` | 动作契约：handler key、input、preconditions（v1.1 语义校验） | camelCase |
| `rules` | 受限 AST 规则（禁止任意源码/eval） | camelCase |
| `policies` | subject/resource/action/field 权限 | camelCase |
| `roleDefinitions` | 角色定义：`description` + `dataScope ∈ {tenant, workspace, aggregated_only}` | camelCase |
| `projections` | 读模型投影定义 | camelCase |
| `connectors` | 数据源映射声明（mapping 细节属 Connector YAML） | camelCase |

未知顶层 key 报 `DSL1002`。

## 4. meta 与 SemVer

```yaml
meta:
  name: daka-business-ontology   # kebab-case，必填
  version: 1.0.0                 # ontology 自身版本，SemVer，必填
  dsl: "1"                       # DSL major version，必填；Runtime 拒绝不支持的 major
  description: ...               # 可选
```

- SemVer 必须匹配 `^(0|[1-9]\d*)\.(0|[1-9]\d*)\.(0|[1-9]\d*)(-[0-9A-Za-z.-]+)?(\+[0-9A-Za-z.-]+)?$`，否则 `DSL1004`。
- DSL 自身按 SemVer 演进：破坏性语法变更升 major；Runtime 只支持已声明的 major 集合（当前 `[1]`）。

## 5. 类型系统

property 的 `type` 只能是：

- 原始类型：`uuid, string, text, integer, decimal, boolean, date, datetime, uri, json`
- 列表：`list<T>`，T 为原始类型（如 `list<string>`）
- 枚举：`type: enum` 且必须带 `ref: <valueSetId>`（缺 ref 报 `DSL1010`；ref 指向是否存在属语义校验）

未知类型报 `DSL1007` 并给出最接近的合法类型建议。

property 允许的属性：`type, ref, required, immutable, security, status, description`。未知属性报 `DSL1008`。`security ∈ {internal, confidential, highly_confidential}`；`status` 为起草标记（`draft | TBD | proposed | confirmed`）。

## 6. linkTypes

```yaml
linkTypes:
  contractGrantsRights: {from: Contract, to: RightsGrant, cardinality: one_to_many}
```

- `cardinality ∈ {one_to_one, one_to_many, many_to_one, many_to_many}`，否则 `DSL1011`。
- `from`/`to` 指向已定义 objectType/interface 属语义校验（P1-C）。

## 7. actions（动作契约）

Action 是**声明式契约**，不含可执行代码；effect 由 Runtime 注册的 handler 实现。

```yaml
actions:
  recordPayment:
    target: PaymentSchedule          # 必填，已定义 objectType
    handler: payment.record          # 必填，Runtime handler 注册键 ^[a-z][A-Za-z0-9_.]*$
    actorRoles: [financeOperator]    # 必填，非空；引用 policies/roleDefinitions 中的角色
    inputs:                          # 与 property 相同类型系统；可空
      amount: {type: decimal, required: true}
      paidAt: {type: datetime, required: true}
    preconditions:                   # 受限 AST 节点数组；可空
      - {op: gt, path: input.amount, value: 0}
    effects: [createPaymentEvent, recalculateScheduleStatus]  # 契约声明（审计/文档用）
    idempotent: true                 # 默认 true；要求调用方提供幂等键
    description: 登记一笔实付
```

非法 handler key 报 `DSL1012`；`target` 不存在、`actorRoles` 为空或引用未定义角色属语义校验（`DSL2xxx`）。

## 8. rules（受限 AST）

`when` 只能是下表操作符组成的 AST；出现任何其他 `op` 或函数字符串报 `DSL1013`。**禁止任意源码、`eval`、模板注入。**

| 类别 | op | 形态 |
|---|---|---|
| 逻辑 | `all` / `any` | `{op, args: [node, ...]}` |
| 逻辑 | `not` | `{op, arg: node}` |
| 比较 | `eq, ne, gt, gte, lt, lte` | `{op, path, value}` 或 `{op, path, valuePath}`（与另一路径比较） |
| 集合 | `in` | `{op, path, value: [...]}` |
| 时间 | `dateBefore` / `dateAfter` | `{op, path, value: now\|<date>\|valuePath, offsetDays?: int}`；与另一路径比较时用 `valuePath` 代替 `value` |
| 存在 | `exists` / `missing` | `{op, path}` |
| 聚合 | `sum` / `count` | `{op, over: <collectionPath>, path?: <field>, as: <name>}`（仅投影/规则上下文） |

```yaml
rules:
  paymentOverdue:
    description: 应付已逾期且未结清
    severity: high                   # info|low|medium|high|critical，必填
    when:
      op: all
      args:
        - {op: dateBefore, path: schedule.dueAt, value: now}
        - {op: gt, path: schedule.unsettledAmount, value: 0}
    result: createOrUpdateRiskFinding   # 声明式结果标识，行为由 Runtime rule executor 注册
```

`path` 为点分隔字段路径；锚点类型必须在 rule 的 `scope`（可空，默认全体）所列类型中存在该字段，否则语义报错。

## 9. policies 与 roleDefinitions

```yaml
roleDefinitions:
  financeOperator: {description: 财务操作, dataScope: workspace}   # dataScope: tenant|workspace|aggregated_only

policies:
  financePaymentWrite:
    effect: allow                    # allow|deny，必填；deny 优先
    roles: [financeOperator]
    resources: [PaymentSchedule, Payment]   # objectType 或 interface
    actions: [read, recordPayment]          # read|write 或 action id
    fields: ["*"]                           # 或字段名列表
    description: 财务可读写付款对象
```

- 默认策略 `deny_unless_granted`：无匹配 allow 即拒绝。
- `resources`/`actions`/`fields` 允许 `"*"` 通配（如只读全量）；字段级规则与属性 `security: highly_confidential` 的默认遮罩叠加生效。
- `roles`/`resources`/`actions`/`fields` 引用存在性属语义校验。

## 10. projections

```yaml
projections:
  paymentCalendar:
    basedOn: [Contract, PaymentSchedule, Payment]   # 必填，引用已定义类型
    description: 付款日历
    metrics:                                        # 可选，投影输出度量声明
      unsettledAmount: {type: decimal, description: 未结清金额}
```

投影是事实的纯推导，不得引入新的权威状态；`basedOn` 引用不存在类型属语义错误。

## 11. connectors

```yaml
connectors:
  yamlContractBatch:
    kind: yaml                       # v1 内置 yaml（模拟源）；其他 kind 由 Runtime 注册
    description: YAML Data Pack 模拟合同批次
    mapping:
      Contract: {idField: contractNumber}
    checkpoint: batchId
```

`mapping` 的 key 必须是已定义 objectType；`kind` 非法报 `DSL1014`。

## 12. 兼容性规则（`ontology diff` 分类）

| 变更 | 分类 |
|---|---|
| 新增 objectType/linkType/valueSet/property(可选)/action/rule/policy/projection | additive |
| 新增必填 property（有默认值）、cardinality 放宽、枚举扩大 | compatible |
| property 删除或改型、枚举缩减、cardinality 收紧、新增必填 property（无默认值）、删除类型/action、action 输入改型或新增必填输入 | breaking |
| property 改型但存在无损转换、cardinality 变化需回填、decimal 精度调整 | data-migration-required |

breaking 变更必须升级 ontology major version；diff 输出的最高级别决定建议的版本升级幅度。

## 13. 诊断

所有诊断携带：稳定 `code`、`severity`、`file`、`line`、`col`、YAML `path`、可读 `message` 与可选 `suggestion`。代码分配：

| code | 含义 |
|---|---|
| **DSL1xxx 语法** | |
| DSL1001 | YAML 解析失败 |
| DSL1002 | 未知顶层 section |
| DSL1003 | meta 缺字段或非法 |
| DSL1004 | 非法 SemVer |
| DSL1005 | 重复 ID |
| DSL1006 | ID 命名违规 |
| DSL1007 | 未知 property 类型 |
| DSL1008 | 未知 property 属性 |
| DSL1009 | section 结构非法（非 mapping 等） |
| DSL1010 | enum 缺/非法 ref |
| DSL1011 | 非法 cardinality |
| DSL1012 | 非法 action handler key |
| DSL1013 | rule 含非法操作符/结构 |
| DSL1014 | 非法 connector kind |
| **DSL2xxx 语义** | |
| DSL2001 | 引用不存在的类型（implements/from/to/target/basedOn/mapping） |
| DSL2002 | 引用不存在的 valueSet |
| DSL2003 | interface 属性实现不一致（类型/required/immutable 冲突） |
| DSL2004 | 引用不存在的角色 |
| DSL2005 | action actorRoles 为空 |
| DSL2006 | rule path 锚点字段不存在 |
| DSL2007 | policy 引用不存在的 resource/action/field |
| DSL2008 | projection basedOn 为空或含重复 |
| DSL2009 | enum ref 类型误用（enum 未带 ref 以外的类型组合） |
| DSL2010 | TBD/draft 标记提醒（warning） |
| **DSL3xxx 编译** | |
| DSL3001 | 生成物写入失败/漂移（check-generated） |
| **DSL4xxx diff** | |
| DSL4001 | diff 输入不是合法 Canonical IR |

## 14. 编译产物（`ontology/.generated/`，禁止手改）

- `ontology.manifest.json` — Runtime 消费的完整 Canonical IR 清单
- `ontology.schema.json` — 每种 objectType 的实例校验 JSON Schema
- `ontology.types.ts` — TypeScript contracts
- `ontology.openapi.json` — Runtime API OpenAPI 片段
- `ontology.index-plan.json` — PostgreSQL 声明式索引计划
- `ontology.fingerprint` — Canonical IR 规范化序列化的 sha256

编译确定性要求：同一目录内容在不同运行顺序/操作系统下产物字节一致（加载顺序按文件名字典序，所有输出 key 字典序排列，换行 LF，无时间戳）。

|---|---|---|---|

## 10. 迁移来源说明

`ontology/schema/v1/` 由 `daka-ontology/ontology/daka.v0.1.yaml`（`0.1.0-draft`，customer_review 讨论骨架）迁移：

- snake_case section 名 → camelCase（`value_sets` → `valueSets` 等）。
- linkType ID snake_case → camelCase。
- `string_list`/`uuid_list` → `list<string>`/`list<uuid>`。
- `principles`/`security`/`persistence`/`open_questions` 属讨论注记，非 authoring section，不迁入 Schema YAML；其约束由 spec 与后续 runtime 文档承接。
- v0.1 中 `status: TBD` 的取值保留为起草标记，待客户确认后在语义校验阶段收紧为 valueSet。
- `actions`/`rules`/`policies`/`projections`/`connectors` 已按本规范第 7–11 节迁入独立文件；v0.1 的 `security.roles` 迁移为 `roleDefinitions` + `policies`。
- 为满足二级市场闭环（PLAN.md 阶段 3 第 3 期四条纵向切片之一），v1 在 v0.1 基础上新增 `MarketObservation`、`ReleaseRecommendation` 对象类型及对应 link/action/projection；`销项权/LEV` 等待确认术语不落枚举。
